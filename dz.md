Конспект: Взаимодействие устройств ЭВМ в процессе выполнения машинной команды (Рабочий цикл процессора)1. Введение: Представление данных и команд в ЭВМПрограмма — упорядоченная последовательность команд, преобразующая входные данные в результат. Исполняемые команды и рабочие данные хранятся в оперативной памяти (ОП), а их выполнение осуществляет процессор.   Представление данных:Числа — в двоичной системе счисления (форматы с фиксированной и плавающей точкой).   Символы — в виде двоичных кодовых таблиц.   Логические векторы — последовательности битов (беззнаковые целые типы).   Структура машинной команды:Содержит КОП (код операции) и адресные поля операндов ($A_1$, $A_2$).   В большинстве архитектур результат операции записывается обратно на место первого операнда ($A_1$).   Система команд процессора — полный набор инструкций, аппаратно поддерживаемых процессором (арифметические, логические, передачи управления, пересылки данных, ввода-вывода).   2. Аппаратное обеспечение процессора и ОПОсновные регистры и блоки процессора:СчАК (СК / PC — Program Counter) — счетчик адреса команд. Хранит адрес ячейки ОП, из которой должна быть считана следующая команда. Разрядность определяется объемом адресуемой ОП.   РК — регистр команд. Хранит код текущей команды на протяжении всего времени ее выполнения.   АЛУ (арифметико-логическое устройство):   Р1 (аккумулятор) — регистр, куда загружается первый операнд и где формируется итоговый результат.   Р2 — регистр для второго операнда.   Порты процессора:ПортА (порт адреса) — передает адрес на шину адреса.   ПортД (порт данных) — передает и принимает данные через шину данных.   УУиС (устройство управления и синхронизации) — координирует работу всех узлов процессора, генерируя управляющие сигналы ($y_i$) на основе тактов генератора и осведомительных сигналов ($x_i$).   DC (дешифратор КОП) — преобразует двоичный код операции в унитарный сигнал конкретной команды.   Регистры оперативной памяти (ОП):РАОП — регистр адреса ОП (принимает адрес с шины адреса).   РСОП — регистр слова ОП (буфер для чтения/записи через шину данных).   Управляющие сигналы ОП:ЧтОП — чтение слова из ОП.   ЗпОП — запись слова в ОП.   3. Рабочий цикл процессора (на примере двухадресной команды)Рабочий цикл состоит из 5 последовательных этапов:   Этап 1. Выборка команды из ОППортА := СчАК — адрес очередной команды выставляется на шину адреса ($y_1$).   ЧтОП — сигнал чтения из памяти ($y_2$).   РК := ПортД — считанный код команды поступает в регистр команд ($y_3$).   Этап 2. Выборка операндов из ОПВыборка первого операнда:ПортА := A1 — адрес первого операнда выставляется в шину адреса ($y_4$).   ЧтОП ($y_2$).   P1 := ПортД — операнд загружается в аккумулятор АЛУ ($y_5$).   Выборка второго операнда:ПортА := A2 — адрес второго операнда выставляется в шину адреса ($y_6$).   ЧтОП ($y_2$).   P2 := ПортД — второй операнд загружается в регистр Р2 ($y_7$).   Этап 3. Выполнение операции в АЛУЗначение КОП из РК поступает на дешифратор DC, формируя сигнал $x_i = 1$.   УУиС в ответ формирует управляющий сигнал $y_i^{АЛУ} = 1$, инициируя нужную микропрограмму в АЛУ.   АЛУ выставляет флаг занятости $Z_{АЛУ} = 1$.   По завершении вычислений результат фиксируется в аккумуляторе $P1$, а сигнал занятости сбрасывается в $Z_{АЛУ} = 0$.   Этап 4. Запись результата в ОП и фиксация признаковПортД := P1 — результат из аккумулятора подается в порт данных ($y_8$).   ПортА := A1 — адрес первого операнда выставляется на шину адреса ($y_4$).   ЗпОП — сигнал записи результата в память ($y_9$).   Обновление регистров признака результата (РПР) и флагов исключений (РФ).   Этап 5. Продвижение счетчика команд (СчАК)СчАК := СчАК + L, где $L$ — длина выполненной команды в байтах.   (Счетчик переходит к указанию на следующую команду; этот шаг может выполняться сразу после первого этапа).   4. Формирование признаков результата и исключенийНа выходной шине АЛУ (ШАЛУ) формируется унитарный код признака результата операции (для сложения, вычитания, инкремента, декремента и логических операций):   ШАЛУ(0) = 1, если результат $P1 = 0$.   ШАЛУ(1) = 1, если результат $P1 < 0$.   ШАЛУ(2) = 1, если результат $P1 > 0$.   ШАЛУ(3) = 1, если произошло переполнение с фиксированной точкой (ППФТ).   Шифратор (Coder) преобразует унитарный 4-битный код в 2-битный позиционный код регистра признака результата (РПР):   00 — результат равен нулю;   01 — результат отрицательный;   10 — результат положительный;   11 — переполнение с фиксированной точкой.   Линии исключений (ШАЛУ(4:7)): переполнение порядка, исчезновение порядка, потеря значимости, деление на ноль. Фиксируются в регистре флагов (РФ) для последующей обработки прерываниями.   5. Команды передачи управления (условный переход по маске)Формат команды: [ КОП (0:7) | Маска M (8:11) | Адрес перехода A (12:n) ]   Связка битов маски с признаком результата (РПР):Значение РПРРазряд маскиУсловие ветвления00РК(8)Результат $= 0$   01РК(9)Результат $< 0$   10РК(10)Результат $> 0$   11РК(11)Переполнение (ППФТ)   Логика работы:Если $M = 0000$ — переход не происходит (эквивалент NOP).   Если $M = 1111$ — безусловный переход.   Если текущее значение РПР совпадает с активным битом в маске $M$, продвинутый адрес в СчАК заменяется адресом перехода: СчАК := A. Иначе выполнение продолжается по естественному порядку.   6. Система прерываний и переключение программ   Прерывание — аппаратный механизм, приостанавливающий текущую программу для обработки внештатной ситуации или внешнего события с гарантией точного возврата назад.   Типы прерываний:Внутренние (исключения) — ошибки вычислений (деление на ноль, переполнение). Не маскируются.   Внешние — запросы от таймеров, клавиатуры, периферийных устройств. Могут быть замаскированы через регистр масок (РМ).   Аппаратная поддержка:РФ (регистр флагов прерываний) — фиксирует биты запросов $F_i$.   РМ (регистр масок) — разрешает или запрещает реакцию процессора на отдельные прерывания.   ТВП (Таблица векторов прерываний) — начальная область ОП, где по адресам $0 \dots n-1$ лежат команды безусловного перехода JMP Ai на подпрограммы-обработчики.   УС (указатель стека) — регистр, указывающий на вершину стека в ОП (организован по принципу LIFO).   Пошаговый алгоритм обработки прерывания:Сохранение адреса возврата в стек:$$\text{ОП}[\text{УС}] := \text{СК}; \quad \text{УС} := \text{УС} + 1$$   Загрузка номера вектора:$$\text{СК} := i$$   Вызов обработчика: Считывается команда JMP Ai из ТВП $\rightarrow \text{СК} := A_i$.   Выполнение подпрограммы обработки: При необходимости обработчик сохраняет в стек регистры общего назначения (РОН) и слово состояния программы (PSW/ССП).   Возврат по команде RETI:$$\text{УС} := \text{УС} - 1; \quad \text{СК} := \text{ОП}[\text{УС}]$$   
Процессор восстанавливает адрес возврата и продолжает прерванную программу с того же места.
